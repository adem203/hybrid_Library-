                    General Introduction

With the rapid evolution of information technology, educational institutions and traditional
libraries are undergoing an important digital transformation. Students and teachers now need
quick and secure access to academic resources, whether they are available physically inside the
library or digitally through online platforms. However, many institutions still manage physical
books and digital educational resources separately, which can make access to information less
efficient.
It is within this context that my end-of-studies internship project at RiseUp was proposed.
The objective of this project is the conception and development of a Secure Hybrid Library
Platform for an academic environment. This platform combines physical library management
with digital resource access in a single system. It allows students to search for books, reserve
or borrow physical resources, access digital documents, and follow their reservations and loans.
It also allows teachers to upload pedagogical resources, while administrators supervise users,
books, documents, reservations, loans, and statistics.
The main purpose of this platform is to provide a centralized, secure, and easy-to-use environ-
ment that improves the management of academic resources. It helps students access learning
materials more efficiently, supports teachers in sharing pedagogical content, and gives admin-
istrators better control over library operations and platform activity.
The development of this project followed a structured and progressive approach. The work
started with analysis and design, then continued with authentication and security, catalog
management, reservations and loans, digital document management, dashboards, notifications,
and final testing.

To present this work clearly, this report is divided into four main chapters:

    · Chapter 1: General Project Context. This chapter presents the host organization,
       the project context, the problem statement, and the study of existing solutions.

    · Chapter 2: Requirements Analysis and Specification. This chapter identifies
       the system actors and describes the functional and non-functional requirements of the
       platform.

    · Chapter 3: Conceptual Study. This chapter presents the UML modeling of the
       system, including use case diagrams, the class diagram, and sequence diagrams.

    · Chapter 4: Implementation and Realization. This chapter describes the develop-
       ment environment, the software architecture, the technologies used, the main application
       interfaces, and the final implemented features.

1.3 Project Context

In the modern educational landscape, access to information and academic resources is a critical
factor in student success. Universities and educational institutions are increasingly moving
towards digital transformation to facilitate learning. However, many institutions still treat
their physical libraries and digital course materials as two separate systems.

    Within this framework, the objective of this project is to conceive and develop a secure
hybrid library platform. This platform aims to modernize the academic experience by bridging
the gap between a traditional physical library and a digital learning environment. By central-
izing physical book management and digital academic resource sharing, the system provides a
unified, accessible, and secure portal for students, teachers, and administrators.

1.3.1 Problem Statement

Currently, managing physical library assets, such as reservations and borrowing, often relies
on manual tracking, while digital resources, such as courses, exams, corrections, TP/TD doc-
uments, and PDF files, are scattered across unintegrated platforms like emails or basic cloud
drives.

    This fragmentation creates several key issues:

    · The absence of a centralized repository for academic resources such as courses, exams,
       corrections, TP/TD documents, and PDF files.

    · Time wasted by students navigating multiple systems to access both physical books and
       digital files.

    · Difficulties for teachers in securely and efficiently distributing educational content.

    Therefore, a dedicated hybrid platform is essential. By combining physical book man-
agement with a secure digital academic space for resource sharing, our system resolves these
inefficiencies and offers a unified, practical solution for the university ecosystem.

       streamable resources, including digital books, educational audio files, historical docu-

       variety of multimedia academic content.

comparing and evaluating the selected solutions. These criteria are related to the main needs

    · Teacher Content Upload: A function that allows educators to upload course materials,

4.2 Development Architecture

The Secure Hybrid Library Platform is based on a client-server architecture. This archi-
tecture separates the application into independent layers, which makes the system easier to
organize, maintain, secure, and extend. Each layer has a specific responsibility and communi-
cates with the other layers through well-defined exchanges.

    The platform is composed of three main layers: the frontend layer, the backend layer,
and the database layer. The frontend layer represents the user interface and allows users to
interact with the application. The backend layer manages the business logic, security rules, API
requests, file uploads, and communication with external services. The database layer stores and
manages all persistent data used by the system.

          Figure 4.1: Development Architecture of the Secure Hybrid Library Platform

                                                           30
    As shown in Figure 4.1, the platform is accessed by three main actors: Student, Teacher, and
Admin. These users interact with the frontend layer, which communicates with the backend
layer through HTTP requests and responses. The backend exposes REST API endpoints, ap-
plies authentication and authorization rules, processes business operations, and communicates
with the PostgreSQL database using the pg library. It also communicates with the Brevo API
to support transactional emails and password reset codes. In-app notifications are managed
inside the platform and displayed directly in the user workspace.

    · Frontend Layer: This layer is developed using React.js. It provides the web inter-
       faces used by Students, Teachers, and Admins. It includes pages and components for
       authentication, book catalog consultation, digital document access, reservations, loans,
       dashboards, and statistics. The frontend also uses React Router for navigation, Ax-
       ios for API communication, i18next for multilingual support, and Recharts for data
       visualization.

    · Backend Layer: This layer is developed using Node.js and Express.js. It receives
       requests from the frontend, applies business rules, manages authentication and autho-
       rization, validates user input, handles file uploads, and communicates with the database.
       The backend contains the main modules of the platform, including authentication, users,
       books, categories, digital documents, reservations, loans, dashboards, notifications, and
       uploads.

    · Database Layer: This layer is based on PostgreSQL. It stores the main data of the
       platform, such as users, books, categories, digital documents, reservations, loans, notifi-
       cations, and other records required by the system. The backend interacts directly with
       the database through the pg library.

    · Security and Services: The platform integrates several security mechanisms, including
       JWT authentication, password hashing with bcryptjs, request validation with express-
       validator, and HTTP security headers using Helmet. It also uses Multer for file upload
       management and node-cron for scheduled tasks.

    · External Services: The platform uses the Brevo API to manage transactional emails
       and password reset codes. Notifications are handled as in-app alerts displayed inside the
       platform.

    This architecture provides a clear separation between the user interface, the server-side
logic, and the database. It also improves the maintainability of the project because each part
of the system can be updated or extended without affecting the whole application structure.

4.4 Security Implementation

Security is an essential aspect of the Secure Hybrid Library Platform, since the system
manages user accounts, academic resources, book reservations, loans, and administrative op-
erations. For this reason, several security mechanisms were implemented in order to protect
access to the platform and ensure that each user can only use the features allowed by their role.

    The security implementation is based on authentication, password protection, role-based
access control, input validation, protected routes, and controlled account creation. These mech-
anisms help reduce unauthorized access and improve the reliability of the system.

4.4.1 Authentication with JWT

The platform uses JSON Web Tokens (JWT) to manage user authentication. When a
user logs in with a valid email address and password, the backend verifies the credentials and

                                                           36
generates a token. This token is then used by the frontend to access protected resources.
    Each protected request sent from the frontend to the backend includes the authentication

token. The backend checks the validity of the token before allowing access to the requested
resource. If the token is missing, invalid, or expired, the request is rejected.

    This mechanism allows the platform to keep user sessions secure while separating public
routes from protected routes.

4.4.2 Password Protection

User passwords are not stored in plain text. During account creation or password update, the
password is hashed using a secure hashing mechanism before being saved in the database.

    This approach protects user credentials because even if the database is accessed without
authorization, the real passwords are not directly visible. Password hashing is therefore an
important security measure in the platform.

    The password reset process is also secured using an email verification code. When a user
forgets their password, a verification code is sent by email. The user must enter the correct
code before being allowed to continue the password reset process.

4.4.3 Role-Based Access Control

The platform uses Role-Based Access Control (RBAC) to separate the permissions of each
user. The main roles are Student, Teacher, and Admin. Each role has access only to the
features related to its responsibilities.

    Students can consult the catalog, reserve or borrow books, access digital resources, and
follow their reservations and loans. Teachers can upload and manage pedagogical resources
and consult statistics related to their documents. Admins have access to management features
such as users, books, categories, documents, reservations, loans, dashboards, and statistics.

    This separation of permissions helps protect sensitive operations. For example, only the
administrator can create and manage user accounts, while students and teachers can only
access their own workspaces.

4.4.4 Protected Routes

Protected routes are used in both the frontend and backend parts of the application. On the
frontend side, users are redirected according to their role after authentication. If a user tries
to access a page that does not belong to their role, the system prevents access.

    On the backend side, middleware functions are used to verify the authentication token and
check the user role before executing protected operations. This ensures that users cannot bypass
the interface and directly call unauthorized API endpoints.

    For example, user management routes are restricted to the administrator, while document
upload routes are reserved for teachers. This improves the overall security of the application.

4.4.5 Input Validation

Input validation is used to verify the data sent by users before processing it on the backend.
This includes checking required fields, email format, password format, identifiers, and form
data.

    Validation helps prevent incorrect or incomplete data from being stored in the database. It
also improves the stability of the application by reducing errors caused by invalid requests.

    The platform applies validation to several operations, such as authentication, user manage-
ment, book management, document upload, reservation requests, and loan processing.

4.4.6 Controlled Account Creation

In this platform, students and teachers cannot create accounts by themselves. User accounts
are created and managed by the administrator. This decision improves security because access
to the platform is controlled by an authorized person.

    The administrator can create accounts, assign roles, update user information, deactivate
accounts, and manage access permissions. This ensures that only approved users can access
the system.
